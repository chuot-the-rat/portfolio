# Application Packet Workflow

Use this workflow for each UI/UX Designer, Product Designer, or UX/Product hybrid application.

## 1) Capture the Posting

- Save the posting URL and date reviewed.
- Copy the role title exactly as written.
- Identify the top 3-5 requirements that appear most decision-making-relevant.
- Classify the role emphasis as one of:
  - `UI craft`
  - `Product design`
  - `UX research`
  - `Design systems`
  - `UX/product hybrid`

## 2) Score Fit Before Editing

- Duplicate `ROLE_FIT_SCORECARD_TEMPLATE.md` for the posting.
- Score each dimension from 1-5 using only current portfolio, resume, and LinkedIn evidence.
- Mark application readiness as:
  - `Ready`: only cover-letter tailoring needed.
  - `Ready with edits`: resume or LinkedIn wording needs a small role-specific adjustment.
  - `Hold`: the posting asks for evidence not currently supported.

Default rule: do not edit portfolio pages for a single posting. Only consider portfolio changes when the same gap appears across multiple strong-fit postings.

## 3) Compare Multiple Roles

- Use `JOB_POST_COMPARISON_TEMPLATE.md` when evaluating three postings at once.
- Prioritize roles where the strongest proof maps to `InkLink`, `ProLog`, or `SideQuest` without stretching claims.
- Prefer postings that value research-informed design decisions, product judgment, interaction design, and visual execution.

## 4) Build the Application Packet

Each packet should include:

- Role-fit scorecard.
- Requirement-to-proof mapping for InkLink, ProLog, and SideQuest.
- Resume first-line check.
- LinkedIn headline/about check.
- 3-5 selected proof bullets from `APPLICATION_MESSAGE_BANK.md`.
- One short recruiter-facing why-me paragraph tailored to the posting.

## 5) Manual Pre-Apply Gate

Before applying, confirm:

- Role title and positioning match the posting.
- Frontend experience is framed as build-aware delivery, not the lead identity.
- Claims are concrete and supported by current case studies.
- Contact and resume handoff still points to `/about` and `/about#resume`.
- No unsupported metrics or inflated impact claims were added.

## 6) Archive the Packet

- Store completed packets in `docs/portfolio-audit/applications/`.
- Use the filename format `YYYY-MM-DD-company-role.md`.
- If a posting exposes a repeated portfolio gap, add it to the next baseline audit instead of making an isolated page edit.
