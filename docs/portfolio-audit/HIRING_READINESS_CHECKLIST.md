# Hiring Readiness Checklist

Use this before each application cycle to keep portfolio, resume, and LinkedIn aligned.

## 1) Positioning Alignment

- [ ] Portfolio hero descriptor uses design-first language (`UI/UX`, `Product Designer`) before technical terms.
- [ ] Resume headline and summary match portfolio positioning (design-first, research-informed, product-thinking).
- [ ] LinkedIn headline/about use the same role framing and avoid developer-first identity.
- [ ] Frontend is described as a support skill, not primary role identity.

## 2) Proof Statements (Top 3 Case Studies)

- [ ] `InkLink` includes explicit assumption -> evidence -> design response -> cuts -> next iteration.
- [ ] `ProLog` includes explicit assumption -> evidence -> design response -> cuts -> next iteration.
- [ ] `SideQuest` includes explicit assumption -> evidence -> design response -> cuts -> next iteration.
- [ ] Each project card shows role/scope/year and a clear value statement.

## 3) Recruiter Scanability

- [ ] 10-second scan: role and best first click are obvious.
- [ ] 30-second scan: at least 2–3 strengths are visible without deep scrolling.
- [ ] 2-minute scan: one case study clearly shows problem -> evidence -> decision -> outcome.
- [ ] Contact and resume actions are visible and functional.

## 4) Message Hygiene

- [ ] No vague claims (`seamless`, `intuitive`, `user-friendly`, `easy to use`) without concrete evidence.
- [ ] No fabricated metrics or inflated impact claims.
- [ ] Team role ownership is specific and honest.

## 5) Release Gate

- [ ] `npm run qa:audit`
- [ ] `npm run qa:metadata`
- [ ] `npm run qa:routes`
- [ ] Optional final pass: `npm run qa:browser`

## 6) Application Packet Gate

- [ ] Role-fit scorecard created from `ROLE_FIT_SCORECARD_TEMPLATE.md`.
- [ ] Job requirements mapped to InkLink, ProLog, and SideQuest proof lines.
- [ ] Resume first line checked against the posting.
- [ ] LinkedIn headline/about checked against the posting.
- [ ] 3-5 proof bullets selected from `APPLICATION_MESSAGE_BANK.md`.
- [ ] Why-me paragraph tailored without unsupported metrics or inflated claims.
